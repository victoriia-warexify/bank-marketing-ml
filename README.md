# Bank Marketing — прогноз отклика клиентов

Проект по бинарной классификации на данных телефонных маркетинговых кампаний португальского банка.

Задача — определить клиентов, которые с большей вероятностью откликнутся на предложение открыть срочный депозит. Помимо сравнения алгоритмов, я проверила, насколько полезны предсказания модели при ограниченном количестве звонков.

## Данные

Датасет содержит 41 188 наблюдений. Целевая переменная `y` показывает, открыл ли клиент депозит. Положительных ответов около 11,3%, поэтому основной метрикой сравнения моделей стала **Average Precision (AP)**.

Признак `duration` исключён из обучения: продолжительность разговора неизвестна до звонка, а модель предполагается использовать для предварительного отбора клиентов.


Исходный набор данных — [Bank Marketing (UCI Machine Learning Repository)](https://archive.ics.uci.edu/dataset/222/bank+marketing), авторы: S. Moro, P. Cortez, P. Rita. В проекте используется подготовленная версия `banking.csv` с числовой целевой переменной.


Для хронологической валидации используется исходный файл `bank-additional-full.csv` из UCI Bank Marketing. В отличие от `banking.csv`, он сохраняет порядок наблюдений по времени.
Файл доступен в архиве `bank-additional.zip` на странице [UCI Bank Marketing](https://archive.ics.uci.edu/dataset/222/bank+marketing).


Исследование выполнялось на Python 3.13.2.

## Ход работы


Исследование разделено на семь ноутбуков:

| Ноутбук | Содержание |
|---|---|

| [03_modeling.ipynb](notebooks/03_modeling.ipynb) | Обучение Logistic Regression и SVM, подбор гиперпараметров, сравнение способов кодирования |
| [04_model_comparison.ipynb](notebooks/04_model_comparison.ipynb) | Оценка моделей на Test, анализ ошибок, подбор порога, ранжирование клиентов и bootstrap-интервалы метрик |
| [05_model_interpretation.ipynb](notebooks/05_model_interpretation.ipynb) | Анализ коэффициентов Logistic Regression и Permutation Importance |

В основных экспериментах использовалось случайное стратифицированное разделение 80/20 и пятифолдовая кросс-валидация. В седьмом ноутбуке отдельно проверено качество на хронологическом разделении данных с использованием TimeSeriesSplit.

Основные функции предобработки вынесены в `src/preprocessing.py`. Преобразования признаков выполняются внутри пайплайнов моделей.


## Результаты


| Модель | Test AP | ROC-AUC |
|---|---:|---:|
| Logistic Regression (One-Hot) | **0.4326** | **0.7925** |
| Linear SVM (One-Hot) | 0.4293 | 0.7904 |
| Logistic Regression (Combined) | 0.4220 | 0.7857 |
| Linear SVM (Combined) | 0.4179 | 0.7823 |
| RBF SVM (Combined) | 0.3986 | 0.7717 |
| RBF SVM (One-Hot) | 0.3920 | 0.7831 |

Наибольший AP на Test показала Logistic Regression с One-Hot Encoding (0.4326), немного опередив Linear SVM (0.4293). RBF SVM уступила линейным моделям по основной метрике.


### Доверительные интервалы

Для оценки неопределённости метрик использовался парный bootstrap (2000 выборок).

| Метрика | Разница LR − SVM | 95% CI |
|---|---:|---:|
| Average Precision | +0.0032 | [−0.0023; 0.0088] |
| Precision@10% | +0.0049 | [−0.0109; 0.0218] |

Оба интервала включают ноль, поэтому убедительного преимущества Logistic Regression над Linear SVM по этим метрикам не обнаружено.

Для дальнейшего анализа выбрана Logistic Regression благодаря вероятностным прогнозам и возможности интерпретации коэффициентов.

При стандартном пороге 0.5 Logistic Regression обнаруживала только 19,7% положительных откликов. Подбор порога на обучающих данных позволил увеличить Recall до 53,8%, а F1 — с 0.3017 до 0.4821.

Отдельно я рассмотрела сценарий, в котором банк может обзвонить только 10% клиентов. Среди 824 наблюдений с наибольшими оценками модели положительный отклик был зафиксирован в 399 случаях.

**Precision@10% составила 48,4%, Lift@10% — 4,30.** Доля положительных откликов в этой группе оказалась в 4,3 раза выше средней по выборке.


## Интерпретация модели

Для выбранной Logistic Regression рассмотрены коэффициенты и Permutation Importance.

Наибольшую важность для прогнозирования показали экономические признаки `emp_var_rate` и `cons_price_idx`. Также заметный вклад внесли месяц контакта, история предыдущих обращений и способ связи с клиентом.

Для проверки совместной важности экономических показателей пять признаков перемешивались одновременно. На валидационной выборке Average Precision снизилась с 0.4473 до 0.2116.

Результаты показывают, что модель сильно зависит от экономической информации. Однако показатели коррелируют между собой, поэтому оценки важности нужно интерпретировать с осторожностью. Они не отражают причинное влияние признаков на открытие депозита.


## Влияние экономических признаков

Дополнительно проведён ablation-эксперимент: Logistic Regression повторно обучалась с разными наборами экономических признаков.

При исключении `euribor3m` и `nr_employed` средний CV AP снизился с 0.4567 до 0.4550. Если оставить только два экономических показателя — `emp_var_rate` и `cons_price_idx` — AP составила 0.4526.

При исключении всех пяти экономических показателей AP снизилась заметнее — до 0.4018.

Результаты показывают, что экономические признаки содержат полезную информацию, но часть из них, вероятно, избыточна. Все сравнения проводились на Train с фиксированными гиперпараметрами; окончательный выбор упрощённой модели потребует дополнительной проверки.


## Хронологическая валидация

Дополнительно проверена Logistic Regression на исходном датасете UCI, где наблюдения расположены в хронологическом порядке. Первые 80% использовались для обучения, последние 20% — для тестирования.

Между периодами значительно изменилась доля положительных откликов: с 6.37% на Train до 30.83% на Test. Также изменились распределения экономических показателей.

Результаты временной кросс-валидации оказались слабыми: средний AP = 0.0760, ROC-AUC = 0.5118.

На финальном хронологическом Test модель показала:

| Метрика | Значение |
|---|---:|
| Average Precision | 0.4905 |
| Baseline AP | 0.3083 |
| ROC-AUC | 0.6719 |
| Precision@10% | 62.26% |
| Lift@10% | 2.02 |

При дополнительной проверке двух последовательных частей Test ROC-AUC снизился с 0.6772 до 0.6271, а Lift@10% — с 2.78 до 1.34.

Дополнительно проверено влияние экономических признаков на временную кросс-валидацию. При сохранении только двух экономических показателей средний AP вырос с 0.0760 до 0.0963, а при исключении всех пяти — до 0.0977.

Основной прирост пришёлся на четвёртый фолд. На остальных фолдах различия были небольшими, поэтому говорить о повышении устойчивости модели нельзя. Сравнение проводилось на Train с фиксированными гиперпараметрами.

Результаты показывают, что модель способна ранжировать отклики на последнем периоде, но её качество заметно меняется со временем.


## Как запустить

Для работы понадобится Python 3.13 и зависимости из `requirements.txt`.

Установить зависимости:

```bash
python -m pip install -r requirements.txt
```

Ноутбуки находятся в папке `notebooks/`.

Основное исследование выполняется последовательно, от `01_eda.ipynb` до `06_feature_ablation.ipynb`.

В `03_modeling.ipynb` обученные модели сохраняются в папку `models/`. Файлы моделей не хранятся в репозитории, поэтому перед запуском ноутбуков 04–06 необходимо выполнить третий.

Для работы `05_model_interpretation.ipynb` и `06_feature_ablation.ipynb` нужен файл `models/logistic_onehot.joblib`.


`07_temporal_validation.ipynb` запускается отдельно от остальных ноутбуков и заново обучает Logistic Regression. Для его выполнения необходимы файлы `data/raw/banking.csv` и `data/raw/bank-additional-full.csv`.



## Ограничения

Первоначальная оценка проводилась на случайном разделении данных. Дополнительная хронологическая валидация показала, что качество модели заметно меняется между периодами.

Временное разделение основано на исходном порядке наблюдений: точные даты контактов в датасете отсутствуют. Кроме того, схема предобработки была разработана в предыдущих экспериментах со случайным разделением.

Показатели Average Precision между периодами нельзя напрямую сравнивать без учёта доли положительного класса.

Высокий Lift@10% показывает качество ранжирования, но не доказывает, что использование модели увеличит количество открытых депозитов. Для оценки экономического эффекта нужны данные о стоимости звонков, доходности депозитов и результаты контролируемого эксперимента.
