# Bank Marketing — прогноз отклика клиентов

Проект по бинарной классификации на данных телефонных маркетинговых кампаний португальского банка.

Задача — определить клиентов, которые с большей вероятностью откликнутся на предложение открыть срочный депозит. Помимо сравнения алгоритмов, я проверила, насколько полезны предсказания модели при ограниченном количестве звонков.

## Данные

Датасет содержит 41 188 наблюдений. Целевая переменная `y` показывает, открыл ли клиент депозит. Положительных ответов около 11,3%, поэтому основной метрикой сравнения моделей стала **Average Precision (AP)**.

Признак `duration` исключён из обучения: продолжительность разговора неизвестна до звонка, а модель предполагается использовать для предварительного отбора клиентов.


Исходный набор данных — [Bank Marketing (UCI Machine Learning Repository)](https://archive.ics.uci.edu/dataset/222/bank+marketing), авторы: S. Moro, P. Cortez, P. Rita. В проекте используется подготовленная версия `banking.csv` с числовой целевой переменной.

Исследование выполнялось на Python 3.13.2.

## Ход работы


Исследование разделено на пять ноутбуков:

| Ноутбук | Содержание |
|---|---|
| [01_eda.ipynb](notebooks/01_eda.ipynb) | Исследовательский анализ данных и связей признаков с целевой переменной |
| [02_preprocessing.ipynb](notebooks/02_preprocessing.ipynb) | Подготовка признаков, кодирование категорий, проверка совпадений между Train и Test |
| [03_modeling.ipynb](notebooks/03_modeling.ipynb) | Обучение Logistic Regression и SVM, подбор гиперпараметров, сравнение способов кодирования |
| [04_model_comparison.ipynb](notebooks/04_model_comparison.ipynb) | Оценка на Test, анализ ошибок, подбор порога и ранжирование клиентов |
| [05_model_interpretation.ipynb](notebooks/05_model_interpretation.ipynb) | Анализ коэффициентов Logistic Regression и Permutation Importance |

Предобработка вынесена в `src/preprocessing.py`. Все преобразования выполняются внутри пайплайнов, чтобы избежать утечки данных при кросс-валидации.

Модели обучались на 80% данных с использованием пятифолдовой стратифицированной кросс-валидации. Оставшиеся 20% использовались для итоговой оценки.

## Результаты


Лучший результат по Average Precision показала **Logistic Regression с One-Hot Encoding**.

| Модель | Test AP | ROC-AUC |
|---|---:|---:|
| Logistic Regression (One-Hot) | **0.4326** | **0.7925** |
| Linear SVM (One-Hot) | 0.4293 | 0.7904 |
| Logistic Regression (Combined) | 0.4220 | 0.7857 |
| Linear SVM (Combined) | 0.4179 | 0.7823 |
| RBF SVM (Combined) | 0.3986 | 0.7717 |
| RBF SVM (One-Hot) | 0.3920 | 0.7831 |

При одинаковом One-Hot Encoding разница между Logistic Regression и Linear SVM составила всего 0.0033 AP на Test. RBF SVM заметно уступила им по основной метрике.

При стандартном пороге 0.5 лучшая модель обнаруживала только 19,7% положительных клиентов. Подбор порога на обучающих данных позволил увеличить Recall до 53,8%, а F1 — с 0.3017 до 0.4821.

Отдельно я рассмотрела сценарий, в котором банк может обзвонить только 10% клиентов. Среди 824 клиентов с наибольшими оценками модели положительный отклик имели 399 человек.

**Precision@10% составила 48,4%, Lift@10% — 4,30.** Доля положительных откликов в этой группе оказалась в 4,3 раза выше средней по выборке.


## Интерпретация модели

Для лучшей Logistic Regression рассмотрены коэффициенты и Permutation Importance.

Наибольшую важность для прогнозирования показали экономические признаки `emp_var_rate` и `cons_price_idx`. Также заметный вклад внесли месяц контакта, история предыдущих обращений и способ связи с клиентом.

Для проверки совместной важности экономических показателей пять признаков перемешивались одновременно. На валидационной выборке Average Precision снизилась с 0.4473 до 0.2116.

Результаты показывают, что модель сильно зависит от экономической информации. Однако показатели коррелируют между собой, поэтому оценки важности нужно интерпретировать с осторожностью. Они не отражают причинное влияние признаков на открытие депозита.


## Как запустить

Для работы понадобится Python и зависимости из `requirements.txt`.

Установить зависимости можно командой:

`python -m pip install -r requirements.txt`

Ноутбуки нужно запускать по порядку, от `01_eda.ipynb` до `05_model_interpretation.ipynb`.

В `03_modeling.ipynb` обученные модели сохраняются в папку `models/`. Файлы моделей не хранятся в репозитории, поэтому перед запуском четвёртого и пятого ноутбуков необходимо выполнить третий.

Для работы `05_model_interpretation.ipynb` требуется файл `models/logistic_onehot.joblib`.


## Ограничения

Модели проверялись на случайном разделении данных, поэтому их качество на будущих маркетинговых кампаниях может отличаться. Для более надёжной оценки потребуется проверка на данных за последующие периоды.

Кроме того, высокий Lift не означает, что использование модели увеличит число депозитов в 4,3 раза. Для оценки реального эффекта звонков нужны контрольная группа и данные об экономике кампании.
