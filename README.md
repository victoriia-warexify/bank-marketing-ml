# Bank Marketing — прогноз отклика клиентов

Проект по бинарной классификации на данных телефонных маркетинговых кампаний португальского банка. Цель — оценить вероятность положительного отклика на предложение открыть срочный депозит до звонка.

Я сравнила логистическую регрессию и SVM, проверила, насколько полезно ранжирование клиентов при ограниченном числе звонков, и отдельно оценила качество на более поздних наблюдениях.

## Основные результаты

Лучшей моделью при случайном разделении стала **Logistic Regression с One-Hot Encoding**.

| Average Precision | ROC-AUC | Precision@10% |
|---:|---:|---:|
| **0.4326** | **0.7925** | **48.4%** |

Это результаты на отложенной тестовой выборке (20% данных). Положительный класс составляет около 11,3% наблюдений. Среди 824 контактов с наибольшими оценками модели положительный отклик был в 399 случаях; **Lift@10% = 4.30**.

Хронологическая проверка дала более слабые результаты: ROC-AUC снизился до **0.6719** на позднем Test, а средний ROC-AUC на временных CV-фолдах составил **0.5118**. Поэтому считать модель готовой к применению на новых кампаниях нельзя.

Подробности — в [ноутбуках](#ноутбуки) и разделе [«Хронологическая проверка»](#хронологическая-проверка).

## Данные и подход

Используется датасет [Bank Marketing (UCI Machine Learning Repository)](https://archive.ics.uci.edu/dataset/222/bank+marketing), авторы S. Moro, P. Cortez и P. Rita. В нём 41 188 записей о контактах с клиентами; целевая переменная `y` показывает, был ли открыт депозит. Одна запись соответствует контакту, а не обязательно отдельному клиенту.

Для основных экспериментов используется `data/raw/banking.csv`. Признак `duration` исключён: продолжительность разговора неизвестна до звонка. Доступность `contact`, `month`, `day_of_week` и `campaign` в момент прогноза также не гарантирована; влияние их исключения проверено отдельно.

Данные разделены на Train и Test в пропорции 80/20 со стратификацией (`random_state=42`). **EDA проводится только на Train**: отложенный Test не используется для изучения связей признаков с `y`, выбора признаков или настройки моделей. Для подбора гиперпараметров применяется пятифолдовая кросс-валидация. Предобработка выполняется внутри `Pipeline`, отдельно на обучающей части каждого фолда.

Для проверки на более поздних наблюдениях используется `data/raw/bank-additional-full.csv`, в котором сохранён хронологический порядок строк.

## Сравнение моделей

Результаты на Test при случайном стратифицированном разделении:

| Модель | AP | ROC-AUC |
|---|---:|---:|
| Logistic Regression (One-Hot) | **0.4326** | **0.7925** |
| Linear SVM (One-Hot) | 0.4293 | 0.7904 |
| Logistic Regression (Combined) | 0.4220 | 0.7857 |
| Linear SVM (Combined) | 0.4179 | 0.7823 |
| RBF SVM (Combined) | 0.3986 | 0.7717 |
| RBF SVM (One-Hot) | 0.3920 | 0.7831 |

Разница между Logistic Regression и Linear SVM небольшая. Парный bootstrap (2000 повторов) дал разницу AP **+0.0032** с 95% доверительным интервалом **[−0.0023; 0.0088]**. Убедительного преимущества одной модели по AP нет; для дальнейшего анализа выбрана логистическая регрессия из-за вероятностных прогнозов и интерпретируемости.

При пороге 0.5 Recall составлял 19,7%. Подбор порога на Train увеличил его до 53,8%, но снизил Precision. Для задачи с ограниченным количеством звонков дополнительно рассмотрено ранжирование клиентов по вероятности отклика.

В анализе важности признаков заметную роль играют экономические показатели. При исключении всех пяти экономических признаков средний CV AP снизился с **0.4567 до 0.4018**. Без признаков `contact`, `month`, `day_of_week` и `campaign` — до **0.4321**.

## Хронологическая проверка

В `07_temporal_validation.ipynb` первые 80% наблюдений из исходного упорядоченного датасета использованы для обучения, последние 20% — для проверки. Для настройки модели применён `TimeSeriesSplit` с четырьмя фолдами.

| Проверка | ROC-AUC | Lift@10% |
|---|---:|---:|
| Случайный Test | 0.7925 | 4.30 |
| Хронологический Test | 0.6719 | 2.02 |

На временных CV-фолдах средний **AP = 0.0760** при среднем базовом уровне **0.0724**, а **ROC-AUC = 0.5118**. Преимущество перед случайным ранжированием на этих фолдах очень небольшое.

На хронологическом Test **AP = 0.4905** при базовом уровне **0.3083**. При этом доля положительных откликов выросла с 6,37% на Train до 30,83% на Test. Из-за этой разницы сравнивать AP между периодами без учёта базового уровня некорректно.

Качество также отличается внутри тестового периода: ROC-AUC в двух последовательных частях Test составил 0.6772 и 0.6271. Модель заметно зависит от периода, на котором её оценивают.

## Ограничения

- Точные даты контактов отсутствуют, поэтому хронологическая проверка опирается на порядок строк исходного датасета. Схема предобработки первоначально разрабатывалась в экспериментах со случайным разделением.
- Без идентификаторов клиентов нельзя гарантировать, что повторные контакты с одним человеком не оказались одновременно в Train и Test.
- Доступность части признаков до звонка не подтверждена. Кроме того, прогноз отклика не показывает, вызвал ли звонок открытие депозита.
- Высокий Lift@10% сам по себе не доказывает экономическую выгоду. Для этого понадобились бы данные о затратах, доходности депозитов и контролируемый эксперимент.

## Запуск

Проект выполнялся на Python 3.13.2. Установка зависимостей:

```bash
python -m pip install -r requirements.txt
```

Ноутбуки `01`–`06` запускаются последовательно. В `03_modeling.ipynb` обученные модели сохраняются в `models/` (эта папка не включена в репозиторий). Для запуска ноутбуков `04`–`06` сначала нужно выполнить третий ноутбук.

`07_temporal_validation.ipynb` запускается отдельно и обучает модель заново. Оба исходных CSV-файла находятся в `data/raw/`.

Проверка тестов:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest tests/ -v
```

Тесты предобработки также запускаются через GitHub Actions при push и Pull Request.
